# How GramSetu uses Gnani models

GramSetu uses two Gnani models, both called live over REST from the backend (the API key never reaches the browser).

| | **Gnani Prisma** (speech-to-text) | **Gnani Timbre** (text-to-speech) |
|---|---|---|
| Endpoint | `POST https://api.vachana.ai/stt/v3` (multipart `audio_file` + `language_code`) | `POST https://api.vachana.ai/api/v1/tts/inference` (JSON) |
| Auth | header `X-API-Key-ID` (from `.env`, server side only) | same |
| Model version | `prisma-v2.5` (the response reports it) | `timbre-v2.5` |
| Audio | 16 kHz mono 16-bit WAV, encoded in the browser from the microphone | WAV, 16 kHz, mono, 16-bit |
| Mode | REST, max 30 s per request (UI countdown) | REST; repeated phrases served from a local cache |
| Code | `backend/app/services/speech/gnani.py` → `GnaniPrismaSTT.transcribe` | `backend/app/services/speech/gnani.py` → `GnaniTimbreTTS.synthesize` |
| Called from | `POST /api/speech/transcribe` (`backend/app/api/routes.py`), used by `frontend/src/components/VoicePanel.tsx` | `POST /api/speech/synthesize`, used by `frontend/src/audio/player.ts` (every assistant message is spoken) |

Shared safeguards: one request at a time (Gnani documents a single active request; a global async lock), at most one
retry, a local usage counter with a daily ceiling (`backend/app/services/usage/guard.py`, shown on `/status`), and a
WAV header fix for Timbre's streaming-style headers (`speech/wav.py`).

## Languages and voices verified with our key

Source: `backend/app/services/speech/verified_capabilities.json`, written only by `scripts/gnani_smoke_test.py` after a
real Timbre synthesis and a non-empty Prisma transcript for that language.

| Language | Prisma | Timbre | Voices used | Where |
|---|---|---|---|---|
| Kannada `kn-IN` | verified | verified | **Saanvi** (GramSetu's voice), **Kavin** (demo user voice) | app default voice; demo video |
| Hindi `hi-IN` | verified | verified | **Nalini** (GramSetu), **Deepak** (demo user voice for the clinic line) | app; demo assets |
| Tamil `ta-IN` | verified | verified | Asmita | app |
| English `en-IN` | verified | verified | Kaveri (app), **Pranav** (video narration) | app; video narration |

Voice audition for the demo video (`scripts/demo/clips.py --audition`, results in `demo_assets/voices.json`): each
user line was synthesised with 2 Kannada voices (Kavin, Saanvi) or 3 Hindi voices (Deepak, Vikrant, Bhavna), and each
clip was transcribed by live Prisma. Every candidate was accepted on the first attempt (character error rate 0 to 0.026
against the written sentence; the one difference was ಖಾತೆನೂ → ಖಾತೆಯೂ, a spoken variant). Kavin was chosen for the user so
that the user and GramSetu (Saanvi) sound clearly different. Narration: Pranav and Kaveri both transcribed exactly;
Pranav was chosen as a third distinct voice.

Latency varies a lot between calls; long replies wait for the whole REST file. Timbre SSE streaming is documented and is
the next step.

## Usage and credits

Gnani's API returns no credit or balance data, so GramSetu keeps a **local request count (not official credits)**. On
2026-11-08 the app counted 81 live calls (40 Prisma, 41 Timbre, of which 1 Timbre call returned a
server error 502 during a rehearsal). The smoke-test script made 11 more calls outside the app counter during the build. The official
balance is at https://app.gnani.ai.

In the final demo take, GramSetu's spoken replies were served from the Timbre cache (generated by live Timbre calls
during the rehearsals), except the receipt, which was a live call. The user's lines were generated with live Timbre
calls during the voice audition and transcribed by live Prisma calls during the take.
